Instrukcja uruchomienia – Test Turinga

Lokalny backend FastAPI + Whisper + DeepSeek + Piper + Cloudflare Tunnel

Najprostszy sposób uruchomienia: 
cd ~/PycharmProjects/turing-test


./scripts/start.sh

Skrypt automatycznie:

  • sprawdza Cloudflare Tunnel,
  • sprawdza GPU / CUDA,
  • sprawdza mikrofon,
  • sprawdza modele Piper,
  • sprawdza konfigurację DeepSeek,
  • sprawdza import aplikacji FastAPI,
  • uruchamia serwer FastAPI.

Nie trzeba ręcznie uruchamiać cloudflared, aktywować środowiska ani wykonywać source scripts/env.sh.

1. Uruchomienie aplikacji

W terminalu:

cd ~/PycharmProjects/turing-test


./scripts/start.sh

Jeśli wszystko jest poprawnie skonfigurowane, na końcu powinien pojawić się komunikat: 

✓ Wszystko wygląda poprawnie.
    

Możesz uruchomić aplikację:
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000

Następnie aplikacja będzie dostępna lokalnie i przez domenę turing-test.pl.

2. Zatrzymanie aplikacji

Serwer FastAPI działa w aktywnym terminalu. 

Ctrl + C

Zatrzymuje to aplikację. Cloudflare Tunnel pozostaje usługą systemową i nie trzeba go zatrzymywać.

Cloudflare Tunnel jest skonfigurowany jako usługa systemowa Linux, dzięki czemu może działać niezależnie od procesu FastAPI.

3. Panel uczestnika – prowadzący

Panel służy do prowadzenia rozmowy z wybranym uczestnikiem.

Alice: https://turing-test.pl/participant/?session=alice Bob: https://turing-test.pl/participant/?session=bob
Uwaga:

Panel /participant jest zabezpieczony przez Cloudflare Access.

Dostęp powinien mieć tylko prowadzący, ponieważ panel może wysyłać zapytania do API DeepSeek.

4. Panel człowieka

Ten adres przekazujemy prawdziwemu uczestnikowi rozmowy.

Uczestnik: https://turing-test.pl/human/?session=bob

Panel człowieka jest publiczny i nie wymaga logowania.

Aktualnie uczestnik odpowiada tekstowo. W przyszłości można tutaj dodać również nagrywanie głosu.

5. Ekran / projektor

Na komputerze podłączonym do projektora otwieramy:

Display: https://turing-test.pl/display/

Ekran pokazuje dwie rozmowy jednocześnie. Strony można przypisać do Alice i Boba, a każdej stronie nadać nazwę wyświetlaną publiczności.

Klikalna lista gotowych konfiguracji znajduje się tutaj:

Linki testowe: https://turing-test.pl/display/links.html

6. Przykładowe ustawienie sceny

Przykład — Alice jako Anna po lewej, Bob jako Michał po prawej: 

https://turing-test.pl/display/?left=alice&leftName=Anna&right=bob&rightName=Micha%C5%82

W tym przypadku:

  • lewa strona = Alice, wyświetlana jako „Anna”,
  • prawa strona = Bob, wyświetlany jako „Michał”.

Można też zamienić strony i użyć innego zestawu imion: 

https://turing-test.pl/display/?left=bob&leftName=Piotr&right=alice&rightName=Zosia

Parametry left i right wybierają sesję (alice albo bob), a leftName i rightName określają podpisy paneli. Alice powinna mieć imię żeńskie, a Bob męskie. Spacje i polskie znaki w adresie są kodowane automatycznie, np. Micha%C5%82 oznacza „Michał”.

7. Typowy przebieg pokazu

  1. Uruchom komputer.
  2. Otwórz terminal.
  3. Uruchom ./scripts/start.sh.
  4. Na komputerze prowadzącego otwórz panel /participant.
  5. Na telefonie / laptopie prawdziwego uczestnika otwórz /human/?session=bob.
  6. Na projektorze otwórz /display/.
  7. Włącz dźwięk na ekranie projektu.
  8. Rozpocznij rozmowę.
  9. Publiczność obserwuje obie rozmowy i próbuje rozpoznać, która jest prowadzona przez AI.

8. Szybka diagnostyka

Jeśli coś nie działa, można uruchomić samą diagnostykę bez startowania serwera: 

cd ~/PycharmProjects/turing-test

source .venv/bin/activate
source scripts/env.sh
uv run python scripts/check_setup.py

Skrypt sprawdza:

  • wersję Pythona,
  • GPU / CUDA,
  • mikrofon,
  • modele Piper,
  • klucz DeepSeek,
  • import aplikacji FastAPI.

9. Przydatne adresy lokalne

Health: http://127.0.0.1:8000/api/health API docs: http://127.0.0.1:8000/docs

Endpoint health powinien zwrócić: {"status":"ok"}

10. Cloudflare Tunnel

Tunnel działa jako usługa systemowa.

Status można sprawdzić poleceniem: 

sudo systemctl status cloudflared

Jeśli z jakiegoś powodu usługa nie działa: 

sudo systemctl start cloudflared

Normalnie nie trzeba tego robić ręcznie — scripts/start.sh sam sprawdza status i uruchamia usługę, jeśli jest zatrzymana.

Gotowe.

W normalnym użyciu wystarczy: 

cd ~/PycharmProjects/turing-test

./scripts/start.sh

Reszta konfiguracji uruchamia się automatycznie.
